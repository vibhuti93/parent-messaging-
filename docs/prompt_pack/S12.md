## S12 — Orchestrator, CLI, Audit, Retention (new)

**Allowed files:** `src/omr_dispatch/orchestrator.py`, `cli.py`, `retention.py`, `tests/test_stage12_orchestrator.py`.

- Orchestrator implements the ADR-0018 application service functions (`validate_batch`, `evaluate_batch`, `build_send_plan`, `approve_batch`, `cancel_batch`, `get_job_status`, `list_review_queue`, `resolve_review_item`, `get_artifact`), enforced at the service boundary with a `Principal` context (`actor_type`, `actor_id`, `org_id`, `roles`). Wires S2→S10 for a batch, completing the walking skeleton (ADR-0013).
- The CLI is a thin wrapper over the service layer; every CLI command requires an explicit `--org-id` parameter. CLI command list: `validate`, `evaluate`, `render`, `audio`, `plan-dispatch`, `dry-run`, `send` (refuses to run unless BOTH LIVE_DISPATCH_ENABLED=true AND DEPLOYMENT_COMPLIANCE_ACKNOWLEDGED=true, alongside verified-contract and not-killed safeguards; any live provider call enforces the same dual-switch check), `report`, `purge`, `review-queue`, `tenant-onboard`, `tenant-suspend`, `sender-configure`, `sender-status`.
- Review queues: quarantined contacts, `REVIEW_REQUIRED` scans, `UNKNOWN_NEEDS_REVIEW` dispatches, audio fallbacks.
- Retention/deletion job per D-13 and ADR-0020; consent-revocation propagation cancels scheduled jobs.
- Audit records include `org_id`, `actor_type`, `actor_id`, are masked and exportable per tenant; privacy tests scan logs and outputs for phone numbers, tokens, names.

**Gate 12:** end-to-end dry run of the golden batch against the local test provider only; counts match S1 (e.g., 17 PTM slips; STU_02/03/04/07/08/09/10/19 not dispatched); rerun produces no duplicate deliveries; purge removes what D-13 says. `pytest -q tests/test_stage12_orchestrator.py`.
