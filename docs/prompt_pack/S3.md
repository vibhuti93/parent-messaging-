## S3 — Deterministic Diagnostics and Contact Hygiene

**Allowed files:** `src/omr_dispatch/diagnostics.py`, `contacts.py`, `models.py` (extend only), `cli.py` (thin skeleton only), `tests/test_stage3_diagnostics_and_hygiene.py`. Do not touch fixtures.

**Tasks**
1. `normalize_indian_mobile(raw) -> str | None`: strip spaces, hyphens, parentheses, `+`; reject alphabetic/malformed input with a recorded reason. 12 digits starting `91` → drop prefix; 11 digits starting `0` → drop trunk prefix. Valid iff `^[6-9]\d{9}$` (a format check only; it does not prove an active parent number or WhatsApp capability).
2. `validate_admission_batch(rows)`: flags for invalid student/guardian numbers, same normalised student/parent number, repeated parent number without verified siblings. Flags are deduplicated and sorted. Dispatch eligibility requires valid + verified guardian contact, non-revoked `OPT_IN` for the purpose, and no unresolved quarantine flags. Provide a manual-resolution status; never bypass quarantine to reach an expected send count.
3. `evaluate_batch(questions, admissions, submissions) -> EvaluationBundle` implementing D-01 to D-05 and ADR-0002 exactly (integer marks, Fraction ratios, threshold comparisons via integer cross-multiplication, Decimal ROUND_HALF_UP display, no float in core). `StudentDiagnosticReport` must carry everything S4 needs: present count, enrolled count, class average, topper score, rank, band, subject diagnostics, easy-missed ids, marks not earned, `requires_ptm_slip`, and the contact eligibility result kept separate from academic fields.
4. ABSENT: rank/percentage null, band `ABSENT`, no subject diagnostics. ID mismatches/duplicates raise; zero-present batch handled explicitly (no division by zero).

**Gate 3:** `tests/test_stage3_diagnostics_and_hygiene.py` using hard-coded values from the S1 table: all 20 students; boundary classifier cases (29.99/30.0/60.0/60.01), exactly 0.75 item accuracy, ties, no attempts, all-absent, negative net, invalid IDs, missing/duplicate responses, bad numbers, unknown/revoked/unverified, duplicate contact, sibling exception; invariants (attempted = correct + wrong, net = gross − bleed, subject totals reconcile). Walking skeleton acceptance criterion (ADR-0013): a thin CLI command runs golden fixture ingestion -> batch evaluation -> basic text -> structured JSON manifest. Run `pytest -q tests/test_stage3_diagnostics_and_hygiene.py`; also re-run S1/S2 suites.
