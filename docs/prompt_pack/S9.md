## S9 — Provider Adapter, Webhooks, Retries

**Allowed files:** `messaging/provider.py`, `whatsapp_cloud.py`, `webhooks.py`, `retry.py`, `tests/test_stage9_provider_and_webhooks.py`, `tests/fixtures/provider_contract/**`.

**Tasks**
- `MessagingProvider` interface and isolated `WhatsAppCloudProvider`; version/base URL from config (pinned in S0). Every provider call resolves credentials, `phone_number_id`, and sender configuration strictly from the calling org's `SenderIdentity` (ADR-0019); no global access token or shared phone-number ID exists. Implement only capabilities verified in S0: media upload with durable media-ID storage, approved template sends, in-window free-form where permitted, audio payload only if verified. Persist provider message IDs and sanitised error classes.
- Retries: error handling classifies provider responses into five classes: `RETRY_SAFE`, `OUTCOME_UNKNOWN`, `OPERATOR_ACTION`, `PERMANENT`, and `UNKNOWN`. Only `RETRY_SAFE` failures are retried automatically, using bounded exponential backoff with jitter and honouring `Retry-After` and verified rate limits. Failures classified as `OUTCOME_UNKNOWN` (HTTP 5xx, network timeouts, connection resets where acceptance is uncertain) or `UNKNOWN` are recorded as `UNKNOWN_NEEDS_REVIEW` and reconciled via webhook evidence—never auto-retried or blind resent. Failures classified as `OPERATOR_ACTION` (auth, payment, quality restrictions) or `PERMANENT` (validation, unsupported type, expired window) fail closed immediately without retry; expired/revoked credentials raise `OPERATOR_ACTION` for that specific org only.
- Webhooks (ADR-0019): single entrypoint demultiplexes incoming events by resolving `org_id` from `entry[].changes[].value.metadata.phone_number_id` before any state transition; verify signature using the org's specific app-secret reference; unknown phone-number IDs are rejected and logged without payload. Persist and deduplicate events; map provider statuses while keeping raw status/timestamp; tolerate duplicates and out-of-order events without regressing state.
- Dry-run mode and cost controls from verified pricing sources; never hard-code unverified prices.

**Gate 9:** real local `HTTPServer` on an ephemeral loopback port capturing paths, headers, multipart, JSON, timing. Payload assertions come from the recorded contract fixture, not assumptions. Cases: 429, 5xx, permanent 4xx, malformed response, timeout after receipt, partial failure, duplicate/out-of-order/unknown webhook, invalid signature, handler retry, unapproved template, closed window, unsupported audio template media, `UNVERIFIED` contract → safe block. Report that green tests prove local request/state-machine behaviour only, not Meta acceptance or delivery.
