## S10 — Scheduler

**Allowed files:** `src/omr_dispatch/scheduler.py`, `tests/test_stage10_scheduler.py`.

- Pure `plan_schedule(event, now, policy)` using `ZoneInfo("Asia/Kolkata")` and injected time; persisted schedules survive restart. Schedules are per org and per assessment (timezone, send window; D-10 Sunday 20:30 IST stays default for OMR). Validate that the event date is a Sunday for the primary OMR window; never label another weekday's 20:30 as the Sunday window.
- Primary `2026-10-18 20:30+05:30` and (only when `reminder_enabled`) reminder `2026-10-19 10:00+05:30` for the event `2026-10-18 14:15+05:30`; distinct idempotency identities.
- Daily message cap pacing and multi-tenant fair scheduling (ADR-0019, ADR-0020): respect per-sender daily message limits, spreading large batches across consecutive eligible days within allowed send windows; order jobs fairly across orgs (Deficit Weighted Round-Robin) to prevent tenant starvation.
- Define late import, missed window, holiday override, provider outage, unapproved template, and events created outside the window; never bypass window rules with free-form content. Single-process lock or shared queue to stop two instances dispatching one job.

**Gate 10:** tests for each case above plus DST-free sanity, restart/recovery, lock contention. `pytest -q tests/test_stage10_scheduler.py`.
