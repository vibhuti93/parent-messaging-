## S8 — Messaging Policy Engine and Durable State (split from v2 Stage 7)

**Allowed files:** `src/omr_dispatch/messaging/policy.py`, `store.py`, `audit.py`, `tests/test_stage8_policy_and_state.py`. No provider HTTP yet.

**Tasks**
1. Policy decision before every send, recorded in the audit log: guardian verified, consent `OPT_IN` and non-revoked for purpose, no quarantine flags, service window state, free-form vs template, template approved and supports the content, account/phone-number/billing prerequisites configured, API contract status. Any failed or unknown check → block/defer with an exact reason code.
2. Tenant-scoped durable repositories: every repository call requires an explicit org context (`org_id`); calls without org context fail closed. PostgreSQL is the target database with RLS as defence in depth (ADR-0007, ADR-0017); SQLite is for local tests only. Append-only dispatch events (`dispatch_events`) with derived status, never destructive in-place overwrites. Persist intent before any provider call. DB-level unique constraints enforce idempotency on `(org_id, idempotency_key)` and deduplication on `(org_id, wamid, status)`. States: `PENDING`, `BLOCKED_CONSENT`, `BLOCKED_HYGIENE`, `BLOCKED_POLICY`, `SCHEDULED`, `UPLOADING_MEDIA`, `SUBMITTED`, `DELIVERED`, `READ`, `FAILED`, `RETRY_PENDING`, `UNKNOWN_NEEDS_REVIEW`, `CANCELLED`.
3. Per-org idempotency key: `sha256(f"{org_id}:{student_id}:{assessment_id}:{purpose}:{channel}:{event_type}")` with no raw phone numbers. One logical delivery per key unless a distinct reminder event is configured.
4. Global kill switch and per-tenant kill switch / pause stop dispatch and cancel pending jobs.

**Gate 8:** STU_02 → zero sends, exact block reason; STU_03/04, 07, 08, 09, 10 blocked; STU_01 and STU_05/06 allowed to proceed to policy-permitted mode; STU_17 eligible only with verified consent; STU_19 blocked; duplicate job invocation yields one logical delivery; state-transition table tests (illegal transitions rejected); restart recovery reloads state. Dual-engine repository contract test suite passes against both SQLite and PostgreSQL. `pytest -q tests/test_stage8_policy_and_state.py`.
